# 日志目录说明

项目原先同时存在 `Log/`、`log/` 和 `logs/`，名称无法表达用途。2026-08-22
统一归并到根目录 `log/`：

```text
log/
├── runtime/                  项目运行、仿真评估、标定、ROS2 和真机日志
│   ├── calib/                相机仿真标定和重投影结果
│   ├── eval/                 MuJoCo/CBF 批量评估
│   ├── hardware/             舵机、手眼、policy reach 和真机抓取
│   ├── ros2/                 ROS2 runtime 日志
│   └── ros2_vision/          视觉节点调试输出
├── colcon/
│   └── root_workspace/       根工作区历史 colcon build 日志
└── orbbec_sdk/
    └── OrbbecSDK.log.txt     Orbbec SDK 自身驱动日志
```

对应关系：

| 原目录 | 新目录 | 内容性质 |
|---|---|---|
| `logs/` | `log/runtime/` | 项目主动写出的业务与实验日志 |
| `log/` | `log/colcon/root_workspace/` | 旧的根工作区 colcon 构建日志 |
| `Log/` | `log/orbbec_sdk/` | Orbbec SDK 驱动日志 |

第一方源码、启动脚本、标定元数据和项目文档中的默认路径已经统一改为
`log/runtime/...`。`rl/logs/` 是 RL 模块内部的评估输出目录，不属于这三个根目录，
本轮没有移动。

统一后的 `log/` 是本地运行数据目录，已由 `.gitignore` 忽略。原先已经被 Git
跟踪的 `logs/` 文件在工作区中仍完整保存在 `log/runtime/`，但版本控制会将这次
整理表现为旧路径删除；后续新日志不会继续进入 Git 历史。

注意：直接在仓库根目录执行没有指定 `--log-base` 的 `colcon build`，colcon 仍可能
在 `log/` 顶层创建新的 build 时间戳目录。项目日常 ROS2 构建应在 `ros2/` 下执行；
需要保留根工作区构建日志时，应显式指定：

```bash
colcon --log-base log/colcon/root_workspace build
```
