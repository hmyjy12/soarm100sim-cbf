# 项目清理审计

审计日期：2026-08-22。

## 1. 必须保留的主干

| 路径 | 理由 |
|---|---|
| `rl/` | PPO 训练、评估、workspace 和 checkpoint |
| `mujoco/` | policy 轻量推理、FK、仿真和 CBF 数学 |
| `ros2/soarm100_interfaces/` | ROS2 message/service/action 接口 |
| `ros2/soarm100_vision/` | 当前 perception/control/hardware 主实现 |
| `ros2/scripts/real/` | 真机任务入口和安全清理 |
| `hardware/so100_plus/`、`hardware/tools/` | 舵机映射与真机工具 |
| `hardware/calibration/` | 相机、手眼、舵机和 policy 映射标定 |
| `models/vision/` | 在线视觉模型权重 |
| `SO-ARM100/Simulation/` 和相关 STL | MJCF/FK/几何运行资源 |
| `anygrasp_sdk/` | AnyGrasp worker 的第三方依赖 |

## 2. 可随时重新生成，不应提交

```text
build/
install/
log/colcon/
ros2/build/
ros2/install/
ros2/log/
**/__pycache__/
**/*.pyc
**/.pytest_cache/
MUJOCO_LOG.TXT
```

这些内容不是源码。当前仓库已经跟踪了部分生成物，仅增加 `.gitignore` 不会让
已跟踪文件自动消失；应在一次独立、已备份的 Git 清理提交中执行取消跟踪，不能
和真机功能修改混在同一次提交。

## 3. 建议归档，不建议直接删除

| 路径 | 当前规模/情况 | 建议 |
|---|---|---|
| `log/runtime/` | 约 754 MB | 保留标定和代表性失败案例，其余按日期压缩归档 |
| `rl/checkpoints/` | `rl/` 总计约 102 MB | 保留当前部署 checkpoint 和关键基线，其余外置 |
| `YoloWork/` | 约 83 MB | 在线只用 `models/vision/` 时，可将训练工程归档 |
| `outputs/` | 约 912 KB | 确认图片不再用于报告后归档 |
| 根目录图片和临时文件 | `4101.png`、`Untitled`、`Log` | 先确认来源，再移动到 `outputs/archive/` |
| `OrbbecSDK_v2.8.7_amd64.deb` | 约 38 MB | 驱动已稳定安装后移至安装包归档目录 |

## 4. 体积大但不能仅凭大小删除

| 路径 | 当前规模 | 风险 |
|---|---:|---|
| `third_party/` | 约 1.5 GB | 包含多个 Orbbec workspace、源码和 install，先确认当前启动脚本使用哪一套 |
| `.git/` | 约 1.1 GB | 历史中包含生成物/大文件；需要 Git 历史治理，不能手工删除对象 |
| `anygrasp_sdk/` | 约 812 MB | 真机 AnyGrasp 依赖，不可按普通缓存删除 |
| `SO-ARM100/` | 约 474 MB | MJCF/STL 和上游机械模型依赖 |
| `models/` | 约 142 MB | 在线推理权重 |

`third_party/` 中同时存在 `orbbec_293_ws`、`orbbec_v1_ws`、`orbbec_ws` 和
`orbbec_sdk_2_8_7_root`。这是最大的潜在清理空间，但必须先从实际相机启动脚本、
`source` 路径和当前成功运行日志确认唯一有效版本，再删除其他副本。

## 5. 可能冗余，但需逐项确认

- `lerobot-main/`：如果运行环境始终使用 Conda 中已安装的 LeRobot，仓库副本可能
  只用于参考；先搜索运行脚本和 `PYTHONPATH` 后再决定。
- `YoloWork/__MACOSX/`：属于 macOS 压缩包元数据，通常没有运行价值。
- 根目录 `ob.sh`：需要确认是否仍是有效启动脚本；有效脚本应迁移到
  `ros2/scripts/real/`，否则归档。
- 多套 `*_before_*`、`*_candidate_*` 标定文件：它们是回滚依据，不应未经审核
  删除；稳定后可移至 `hardware/calibration/archive/`。
- `link_self_occupancy_scan*.json` 与采集日志：在线模型验证稳定后，原始扫描可压缩
  归档，但当前仍处于算法验证阶段。

## 6. 推荐清理顺序

1. 提交或备份当前真机代码和标定结果；
2. 单独取消 Git 对 `__pycache__`、`.pyc`、colcon build/install/log 的跟踪；
3. 确认唯一在用的 Orbbec workspace，归档其余版本；
4. 将历史运行日志按日期压缩，只保留索引和代表性数据；
5. 确认 `YoloWork/`、`lerobot-main/` 是否仍承担运行依赖；
6. 最后再考虑 Git LFS 或清理 Git 历史中的大模型和生成物。

不要在同一个提交中同时进行“删除大量文件”和“修改真机控制逻辑”。前者应成为
独立维护提交，便于审查和回滚。
