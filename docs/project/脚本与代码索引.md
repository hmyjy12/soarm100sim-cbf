# 脚本与代码索引

这份文档帮你回答两个问题：

- 一堆 `.sh` 到底哪个该跑？
- 一堆 `.py` 到底哪个是主代码，哪个是辅助工具？

先记住一个原则：`.sh` 大多是“启动器”，`.py` 才通常是“真正干活的代码”。

## 最常用入口

| 你想做什么 | 先用哪个脚本 | 它会启动谁 |
|---|---|---|
| 启动 Orbbec RGB-D 相机 | `ros2/scripts/real/run_orbbec_rgbd.sh` | Orbbec ROS2 camera |
| 测静态 cup 避障 reach | `ros2/scripts/real/run_policy_reach_static_cup.sh` | 相机检查、cup 分割、障碍点云、policy reach、硬件控制 |
| 跑通用 policy reach | `ros2/scripts/real/run_policy_reach.sh` | policy reach 主链路 |
| 只测固定 YOLO + SAM mask | `ros2/scripts/real/run_fixed_yolo_sam_mask.sh` | `target_segmenter_node.py` |
| 只看硬件关节状态 | `ros2/run_hardware_state.sh` | `hardware_joint_state_node.py` |
| 启动硬件 controller | `ros2/run_hardware_controller.sh` | `hardware_controller_node.py` 和 `hardware/tools/run_hardware_controller.py` |
| 单关节调试 | `ros2/run_single_joint_service.sh` | `hardware_single_joint_service_node.py` |
| 抓取实验 | `ros2/scripts/real/run_single_grasp_2real.sh` | AnyGrasp、policy、硬件 controller |

## 实机避障这条主线

```text
run_policy_reach_static_cup.sh
  -> run_policy_reach.sh
  -> target_segmenter_node.py
  -> obstacle_cloud_node.py
  -> policy_reach_node.py
  -> mujoco/cbf.py
  -> hardware_controller_node.py
  -> hardware/tools/run_hardware_controller.py
```

白话：

- `run_policy_reach_static_cup.sh`：静态杯子避障的推荐按钮；
- `run_policy_reach.sh`：通用大启动器，参数很多；
- `target_segmenter_node.py`：找 cup，输出 mask；
- `obstacle_cloud_node.py`：把 mask 和 depth 变成障碍物点云；
- `policy_reach_node.py`：每轮读取关节、跑 policy、调用 CBF、发目标关节；
- `mujoco/cbf.py`：真正算“离障碍多近、动作要不要改”；
- `hardware_controller_node.py`：ROS2 里的硬件代理；
- `hardware/tools/run_hardware_controller.py`：真正和舵机串口通信。

## 建议命名习惯

以后新增脚本，尽量按这个规则：

```text
ros2/scripts/real/run_xxx.sh        真实机械臂会动的入口
ros2/scripts/real/check_xxx.py      只检查，不动机械臂
ros2/scripts/real/capture_xxx.sh    采集姿态/数据
scripts/maintenance/xxx.sh          整理、清理、维护脚本
docs/project/xxx.md                 项目结构说明
```

这样以后不会所有东西都堆在根目录。
