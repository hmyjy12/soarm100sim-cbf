# 避障加动态所有新增修改

## 1. 文档目的

本文是当前已合入的 CBF、waypoint、动态障碍仿真、评测与 sweep 能力的技术总说明。它把共享库默认、仿真增强配置和当前真机配置分开，避免把仿真实验能力误认为已在真机启用。

配套的 [MuJoCo CBF Demo Guide](MuJoCo_CBF_Demo_Guide.md) 只保留运行命令、复现、sweep
和常见问题；真机几何诊断保留在独立文档中，不与仿真说明混合。

本文使用“原有实现”“后续扩展”“当前显式配置”等客观表述，不对无法由历史唯一确认的行做个人归因。

## 2. 三层配置边界

| 层级 | 当前默认/设置 | 不会自动启用的能力 |
|---|---|---|
| Shared CBF library | 9-point、qp_metric=identity、target_guidance=false、lookahead 0.0、unsafe bypass false | 17-point、任务保持 QP、waypoint、动态障碍运动 |
| Simulation enhanced | 17-point、task-preserving、weight 5.0、guidance/filter/bypass true | 真机视觉速度估计、真机动态运动 |
| Real robot current | 9-point、identity、single arm、静态 cup、障碍速度 0、lookahead 0 | WaypointManager、MotionRunner、sweep、dual-arm |

真机当前调用链为：

~~~text
policy_reach_node.py
  → 动态加载 mujoco/cbf.py
  → CbfConfig(capsule_sample_count=9, qp_metric="identity")
  → 每周期 solve_cbf_correction()
~~~

## 3. 一帧控制流程与入口

~~~text
state
  → obstacle refresh
  → （仅 target_guidance=true）optional waypoint
  → nominal action
  → geometry / barrier construction
  → QP correction
  → （按配置）optional unsafe bypass / correction filter
  → final action
~~~

CBF 是局部安全修正，不是完整路径规划器。默认 runtime 不启用 waypoint；仿真增强入口才显式启用 target guidance。

| 入口 | 职责 | lookahead 默认 |
|---|---|---:|
| mujoco/play.py | 单局可视化、target-bank 重放 | 2.0 |
| mujoco/eval_cbf.py | 静态固定杆评测 | 0.0 |
| mujoco/eval_random_rod_sdf.py | 静态随机杆评测 | 0.0 |
| mujoco/eval_sdf_challenge.py | 动态障碍 challenge | 2.0 |
| scripts/sweep_dynamic_obstacles.py | 多 seed/motion 批量评测 | evaluator 默认 2.0 |

## 4. 原有基础与当前合入扩展

原有单臂静态链路包括：名义关节动作、几何/点云障碍表示、胶囊/监视点距离、CBF correction 与静态评测入口。后续扩展保持这些共享默认兼容，并通过 config 或 CLI 显式开启新行为。

| 功能 | 当前正式接口 | Shared 默认 | 仿真入口设置 | 真机当前设置 |
|---|---|---:|---:|---:|
| Capsule sampling | capsule_sample_count / --cbf-capsule-samples | 9 | 17 | 9 |
| QP metric | qp_metric | identity | task_preserving | identity |
| 任务保持权重 | task_preserve_weight | 1.0（identity 时无效） | 5.0 | 不启用 |
| Target guidance | target_guidance | false | true | 不接入 |
| CBF correction filter | enable_cbf_correction_filter | true | true | 不使用 simulation runtime |
| Unsafe bypass | cbf_bypass_filter_when_unsafe | false | true | false |
| Dynamic padding | dynamic_obstacle_lookahead_steps | 0.0 | 入口决定 | 0.0 |
| Obstacle motion | --obstacle-motion | 不适用 | 默认 none，显式选择 | 不适用 |

## 5. CBF 核心接口

共享默认刻意保持 legacy / real-safe：

~~~text
capsule_sample_count = 9
qp_metric = "identity"
task_preserve_weight = 1.0
target_guidance = false
dynamic_obstacle_lookahead_steps = 0.0
~~~

lambda_cbf 与 task_preserve_weight 是两个独立概念。后者只在 qp_metric=task_preserving 时参与 Hessian；旧的 CbfConfig(...) 与单臂 solve_cbf_correction(...) 调用不传新字段仍可工作。

### 9 点与 17 点采样

当前模型按 7 条 capsule 与 5 个点监视器计算，每障碍的距离查询数量为：

~~~text
9-point： 7 × 9 + 5 = 68
17-point：7 × 17 + 5 = 124
~~~

17-point 约为 1.82 倍距离查询，提高每段 capsule 上寻找最危险位置的密度；它不等同于把 QP 约束数简单翻倍。

### Task-preserving QP

共享 identity metric：

~~~text
H = I
~~~

仿真增强 metric：

~~~text
H = I + task_preserve_weight * J_tcp^T J_tcp
~~~

I 保持 Hessian 正定。任务保持项只在显式选择 task_preserving 时计算，未改变真机 identity 行为。

## 6. 动态 CBF、waypoint 与 motion

动态 padding 为：

~~~text
padding = dynamic_obstacle_lookahead_steps * ||obstacle_velocity||
~~~

因此 obstacle velocity 为 0 时 padding 为 0，退化为旧静态行为。WaypointManager 仅在 target_guidance=true 的 simulation runtime 中介入目标；导入 runtime 或构造默认 config 不会启用它。

| 入口 | 默认 lookahead |
|---|---:|
| Shared CbfConfig | 0.0 |
| mujoco/play.py | 2.0 |
| mujoco/eval_sdf_challenge.py | 2.0 |
| mujoco/vision_preview.py | 2.0 |
| mujoco/eval_cbf.py | 0.0 |
| mujoco/eval_random_rod_sdf.py | 0.0 |

所有入口使用 --cbf-dynamic-lookahead-steps，用户传参可覆盖默认。

MotionSpec / MotionRunner 支持 circle、line、random、random_depart 与 random_depart_probe。默认 motion 为 none；同一 seed 与同一配置生成同一运动轨迹。它们只用于 MuJoCo 仿真。

## 7. 仿真评测、指标与 sweep

eval_cbf.py 和 eval_random_rod_sdf.py 面向静态评测；eval_sdf_challenge.py 面向动态 challenge。动态 evaluator 先扫描 target bank，选出会碰杆的 challenge targets；随后 none（无 CBF 对照）和 geom（CBF）在同一 target 列表和同一障碍轨迹上评测。

- target seed 由 --seed 控制；比较配置时应固定。
- obstacle trajectory 由 --obstacle-motion-seed 控制；相同值和相同参数可复现。
- 动态严格评测默认锁直立，避免碰撞倒杆改变预设位置/速度轨迹；--obstacle-can-fall 只适合 viewer 观察。

summary.json 的主要指标为：

| 指标 | 含义 |
|---|---|
| contact_rate | 碰杆局比例，越小越好 |
| reach_2cm_rate | 曾进入目标 2 cm 的比例 |
| safe_reach_2cm_rate | 未碰杆且进入目标 2 cm 的比例 |
| mean_best_dist_m | 各局最佳目标距离均值 |
| mean_end_dist_m | 终止时目标距离均值 |
| mean_max_obs_speed | 障碍最大速度统计 |

无接触不等于完成任务，到达目标也不等于安全完成；应结合 safe_reach_2cm_rate、接触率和距离指标判断。

scripts/sweep_dynamic_obstacles.py 通过 subprocess 调用 mujoco/eval_sdf_challenge.py，扫描 motion、obstacle seed、amplitude 与 period。

- 默认：random、random_depart 两种 motion × 42、43、44、45 四个 seed，共 8 个场景；
- 每组读取 evaluator 的 summary.json；
- 汇总写入 sweep_summary.csv 与 sweep_summary.md；
- 默认输出目录：logs/eval/dynamic_obstacle_sweep/；
- 相同 target seed、obstacle seed 与 motion 参数可复现；
- /logs/ 已由 .gitignore 忽略，运行产物不应提交。

脚本不含 --trials 参数；需要多次试验时，显式提供多个 --obstacle-seeds。--skip-existing 默认开启。

## 8. 真机边界与未合入实验

当前真实 policy_reach 只运行静态单臂 cup CBF：9-point、identity、障碍速度 0、lookahead 0。它不使用 waypoint、MotionRunner、仿真 sweep 或随机动态运动。

以下内容不是当前正式合入能力，只能视为 experimental / future work：

- dual-arm CBF、inter-arm constraints、joint QP；
- obstacle_motion_observer.py；
- guided_target_* trajectory telemetry；
- 真机动态障碍速度 observer；
- 真机 geometry diagnostic 的独立文档与运行链路。

## 9. 验证状态

已完成：

- shared config、AST 与 staged-tree 静态检查；
- pure-Python MotionSpec / MotionRunner smoke；
- 相同 seed 的运动可复现检查；
- evaluator / sweep CLI 与 command-construction 静态检查；
- git diff --check。

尚未完成：

- MuJoCo model-level FK/Jacobian/QP regression；
- GUI/physics regression；
- 长时间完整动态 benchmark；
- 本轮 simulation 修改对应的真机 regression。

因此当前状态是“接口与静态配置已验证”，不是“所有动力学与真机行为已全面验证”。
