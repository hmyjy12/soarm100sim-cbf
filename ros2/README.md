# SO-ARM100 ROS2 Workspace

This directory is the ROS2 workspace for the deployable control path. MuJoCo
remains independent under `../mujoco/`; starting a script from this directory
does not replace or modify `mujoco/play.py`.

## Canonical responsibilities

```text
ros2/
├── soarm100_interfaces/       # ROS messages, services, and actions only
├── so100_plus_description/    # URDF, RViz, FK comparison tools
├── soarm100_vision/           # Current Python implementation package
│   ├── launch/                # Launch descriptions
│   ├── soarm100_vision/       # Nodes and reusable algorithm cores
│   └── test/                  # Unit tests for pure helpers
├── config/
│   ├── real/                  # Real-camera, transform, workspace, safety config
│   ├── sim/                   # ROS2-through-MuJoCo regression config
│   └── experiments/           # Reproducible experiment presets
├── docs/                      # Architecture and deployment notes
└── scripts/
    ├── real/                  # Future canonical real-robot entry scripts
    ├── sim/                   # Future ROS2-through-MuJoCo entry scripts
    └── calibration/           # Future camera/hand-eye orchestration scripts
```

`config/` and `scripts/` are intentionally introduced before the next 2Real
reach-and-avoidance implementation. New code must use these directories;
existing root-level `run_*.sh` scripts remain compatibility entry points until
their replacements have been verified on both hardware and simulation.

## Current package boundary

`soarm100_vision` is a historical package name. It currently contains more
than vision: perception, SDF-CBF-QP, grasp orchestration, MuJoCo adapters,
hardware ROS nodes, and calibration nodes. Splitting it into several ROS
packages now would alter imports, console entry points, launch files, and the
working calibration/controller flow. It is deliberately deferred.

The next implementation must keep its files conceptually separated inside the
existing package:

```text
perception: obstacle_cloud_node.py, target_segmenter_node.py,
            wrist_tracker_node.py, vision_utils.py
safety:     sdf_cbf_core.py, sdf_cbf_backend_node.py
control:    policy_backend_core.py, grasp_core.py, grasp_orchestrator_node.py
hardware:   hardware_controller_node.py, hardware_joint_bridge.py,
            hardware_joint_state_node.py
simulation: mujoco_* files
calibration: wrist_handeye_*, orbbec_eye_to_hand_*
```

When the real reach-and-avoidance path is stable, these groups can be split
into `soarm100_perception`, `soarm100_safety`, `soarm100_control`, and
`soarm100_hardware` packages in one dedicated refactor.

## Execution modes

| Mode | Canonical owner | MuJoCo dependency |
|---|---|---|
| Existing standalone simulation | `../mujoco/play.py` | Required |
| ROS2 algorithm regression in MuJoCo | `ros2/scripts/sim/` | Required |
| Real reach / avoidance | `ros2/scripts/real/` | None |
| Camera and hand-eye calibration | `ros2/scripts/calibration/` | None |

No ROS2 launch file is permitted to silently invoke `mujoco/play.py`. A ROS2
simulation backend must be selected explicitly in its launch/script arguments.

## Runtime directories

`build/`, `install/`, `log/`, and `logs/` are generated by colcon or runtime
execution. They are not source code and should never be treated as the place
to edit a feature. Source changes belong in the package directories above.
